## Key findings so far

- Extension is at v0.1.3 (config.json), ported from upstream ~v0.1.3
  (2026-08-16). Upstream is now at **v0.12.0** (2026-09-25) — ~3,600 added
  lines in `lnurl_mint/`, a **protocol-breaking rewrite**.
- New protocol: notes are BIP-341 taproot output keys `Q`, stored under
  `hex(Q)`. Wire values are bech32m: `cp1<Q>` (note key), `ck1<Q><sig>`
  (key-path spend, BIP-340 schnorr over canonical tx sighash), `cw1`
  (script-path spend: leaf+control block+witness+signed nLockTime/nSequence),
  `cs1<sig>` (issuance cert, amount encoded in HRP like BOLT-11),
  `cx1<P||chaincode>` (watch-only derivation branch export).
  Bearer-note short form: 64-hex in k1 position = preimage; 64-hex where cp1
  goes = h (image). NUMS internal key + `OP_SHA256 <h> OP_EQUAL` leaf.
- Upstream removed old-protocol compatibility code (#67) — new spec is NOT
  backward compatible with what the extension currently serves.
- New upstream modules vs extension:
  - `derivation.py` — cx1 branch derivation (P + tweak·G via tagged hash
    "LNURLcash/derive", purposes 0/1/2). Pure python + coincurve. Portable.
  - `bech32m.py` — cp1/cs1/cx1/npub codecs on `bech32` lib primitives. Portable.
  - `spend.py` — thin wrapper over `lnurlcashkernel` (decode/verify spends).
  - `nostr.py` — NIP-57 zap receipts, publish-only via websockets.
  - `router.py` — grew to 1497 lines: well-known lnurlp/{username}, POST/DELETE
    /p/{username} username registration w/ schnorr ownership proofs
    ("LNURLcash:register:<domain>:<username>"), NIP-05 nostr.json, zaps via
    `?nostr=` kind-9734, internal-transfer metadata (["text/xpub","<cx1>:<i>"]),
    hash lookup, retry rule.
  - `spark.py`, `node.py`, `config.py`, `server.py`, `frontend.py` — standalone
    app plumbing, mostly N/A for LNbits (LNbits core APIs replace them).
- Signing changed: cs1 cert message is "Lightning Signed Message:"-wrapped
  double-sha256 over `LNURLcash:<amount_msat>:<hex(Q)>`, recoverable ECDSA
  r‖s‖recid. Upstream uses node signmessage RPC or spark seed-derived key;
  extension already has per-mint coincurve keypair (Option B) — keep that,
  just switch digest wrap + cs1 encoding. coincurve already used in repo.
- Registration proofs are BIP-340 schnorr over sha256("LNURLcash:<action>:<domain>:<username>").

## THE dependency question (unresolved decision)

`lnurlcash-kernel` (PyPI 0.1.0) = ~1100 lines pure Python + bundled
`libbitcoinkernel.so`. Wheels: manylinux x86_64/aarch64 ONLY + sdist (needs
cmake Bitcoin Core build). No macOS wheel. CLAUDE.md constraint says NO new
Python deps beyond LNbits' pyproject — kernel is a hard violation AND
platform-fragile.

What needs the .so: arbitrary `cw1` script execution only.
What is pure-python portable (already read, in /tmp/lck/wheel):
- encoding.py (bech32m + ck1/cw1 decode), taproot.py (output_key, tweak,
  preimage_note, NUMS_H), sighash.py (canonical-tx BIP-341 sighash),
  policy.py (timelock claims), script.py (OP_SUCCESS/leaf-version check).
- `ck1` verify = schnorr verify over key_path_sighash(Q, domain) — coincurve
  can do this in-extension, no kernel needed.
- bearer short form = sha256(preimage)==h check, Q derived via preimage_note.
- arbitrary cw1 = genuinely needs kernel. Options: (a) optional import —
  reject non-bearer cw1 when unavailable; (b) add dep anyway (Linux-only
  installs); (c) skip cw1. NOT YET DECIDED — ask user.
