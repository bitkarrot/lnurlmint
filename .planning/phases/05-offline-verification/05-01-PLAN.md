## Phase Goal

**As a** wallet holder, **I want to** see the mint's `mintPubkey` advertised on the withdrawRequest endpoint **so that** I can verify rotate/split/merge signatures offline against the mint's own public key without trusting the mint online.

## Acceptance Criteria

- [ ] `lnurlmint/signing.py` exists and provides `mint_pubkey(mint) -> Optional[str]`, `async sign_note(h, amount_msat, mint) -> Optional[str]`, and `verify_note(mint_pubkey_hex, h, amount_msat, signature_hex) -> bool`.
- [ ] `mint_pubkey(mint)` returns the compressed public key hex derived from `mint.mint_privkey` via `coincurve.PublicKey.from_secret_key`; returns `None` if the privkey is empty or invalid.
- [ ] `sign_note(h, amount_msat, mint)` returns a 130-char hex string (65-byte recoverable signature) over `sha256(LNURLcash:<amount_msat>:<h>)`; returns `None` on any exception (never raises); logs a warning on failure.
- [ ] `verify_note(mint_pubkey_hex, h, amount_msat, signature_hex)` recovers the pubkey via `PublicKey.from_signature_and_message` and returns `True` iff it matches `mint_pubkey_hex`; returns `False` on any error.
- [ ] `services.py` no longer contains the stub `sign_note` function body; it re-exports `sign_note` from `signing.py` (`from .signing import sign_note`).
- [ ] `GET /lnurlmint/w/{mint_id}?k1=...` includes `"mintPubkey": <66-char hex>` in the JSON response (the mint's own public key).
- [ ] `mint_pubkey` derivation is computed each call (no cache); a corrupt/empty privkey yields `None` (never a 500).
- [ ] No new Python dependencies are added (`coincurve` already in LNbits).
- [ ] All existing Phase 2 + Phase 3 + Phase 4 tests still pass.

## Artifacts This Phase Produces

This plan creates the `signing.py` module (the per-mint keypair signing core),
replaces the `sign_note` stub in `services.py` with a real re-export, and
advertises `mintPubkey` on the `/w` withdrawRequest endpoint. The signature
inclusion in `/w/cb` responses (sig/sig2) and the `test_offline_verification.py`
port are deferred to Plan 05-02. After this plan, `sign_note` returns real
signatures (no longer `None`), but `/w/cb` still discards them until Plan 05-02
wires them into the response.
