## Phase Goal

**As a** wallet holder, **I want to** receive `sig`/`sig2` signatures on rotate/split/merge responses **so that** I can verify the new notes offline against the mint's advertised `mintPubkey` without trusting the mint online — and a signing failure never blocks my note operation.

## Acceptance Criteria

- [ ] `GET /lnurlmint/w/cb/{mint_id}` rotate/merge response includes `sig` (over `LNURLcash:<merged_amount>:<h>`) when `sign_note` returns a non-None value; `sig` is omitted when it returns None.
- [ ] `GET /lnurlmint/w/cb/{mint_id}` split response includes `sig` (over `LNURLcash:<amount>:<h>`) and `sig2` (over `LNURLcash:<change_amount>:<h2>`); each omitted independently when its `sign_note` returns None.
- [ ] The melt response is unchanged: `{"status": "OK"}` (no `sig`/`sig2`).
- [ ] The response is a plain dict built conditionally — only non-None `sig`/`sig2` keys are included (so `"sig" not in data` holds when signing fails).
- [ ] `test_offline_verification.py` is ported and passes against LNbits fixtures: rotate/split/merge return verifiable `sig`/`sig2`, `verify_note` recovers the correct pubkey, melt carries no sig, wrong amount/k1/pubkey fail verification.
- [ ] A test confirms signing failure is swallowed: monkeypatching `sign_note` to raise still returns `{"status": "OK"}` with no `sig`.
- [ ] A test confirms signing failure is logged (a warning containing "sign_note").
- [ ] A test confirms `mintPubkey` on `/w` matches the pubkey derived from `mint.mint_privkey`.
- [ ] All existing Phase 2 + Phase 3 + Phase 4 tests still pass.

## Artifacts This Phase Produces

This plan wires the `sign_note` return value (real since Plan 05-01) into the
rotate/split/merge responses of `/w/cb`, and ports `test_offline_verification.py`
from the source against LNbits test fixtures. After this plan, a holder receives
`sig`/`sig2` on rotate/split/merge and can verify them offline against the
`mintPubkey` advertised on `/w` (Plan 05-01) using `verify_note` (test-only).

<threat_model>
ASVS Level: 1 | Blocking Threshold: high

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Signing failure blocks a rotate/split/merge (funds stuck) | high | sign_note returns None on any error (never raises); /w/cb builds the response dict conditionally — a None sig is omitted, the swap already committed, status is OK |
| Signature over wrong amount/note (forgery / wrong commitment) | high | sign_note is called with the exact new-note amount and the WALLET-supplied h/h2 (the same values swap minted); test_signature_does_not_verify_against_wrong_amount/k1 lock this |
| sig/sig2 leaked for melt (no holder to verify) | low | Melt response unchanged — no sig/sig2 keys; melt burns a note, no new note to sign |
| verify_note imported by production code | medium | verify_note is test-only (docstring); grep guard in CI / review ensures no production import |
</threat_model>
