## Phase Goal

**As a** wallet holder with no Lightning node of my own, **I want to** poll the LUD-21 verify endpoint to check whether my mint invoice or melt payment has settled, **so that** I know when to claim my note or confirm my melt — with the guarantee that the preimage is only served when it's not a bearer secret (comment-protected mints and melts).

## Acceptance Criteria

- [ ] `GET /lnurlmint/verify/{mint_id}/{payment_hash}` returns `{"settled": bool, "preimage": str|null, "pr": str}` for a comment-protected mint.
- [ ] If `mint.verify_enabled` is False, the endpoint returns HTTP 404 with `{"status":"ERROR","reason":"Not found"}`.
- [ ] If the payment_hash belongs to a no-comment mint, the endpoint returns 404 (preimage IS the secret).
- [ ] If the payment_hash belongs to a melt, the endpoint serves unconditionally (settled, preimage, pr).
- [ ] If the payment_hash is not found in either mints_records or melts, the endpoint returns 404.
- [ ] The preimage is fetched live via `get_standalone_payment` on every call; if unavailable, `preimage` is null.
- [ ] `settled` for a mint is True when the `minted` flag is 1; `settled` for a melt is True when the `settled` flag is 1.
- [ ] The response model `LnurlPayVerifyResponse` has fields `settled: bool`, `preimage: Optional[str] = None`, `pr: str`.
- [ ] No preimage or secret is logged (SEC-05).

## Artifacts This Phase Produces

This plan adds the LUD-21 verify endpoint with comment-protection gating and a
real off-switch. The endpoint reports settlement status for mint invoices and
melt payments, keyed by `payment_hash`. The preimage is fetched live from
LNbits' `get_standalone_payment` (never cached — SEC-02). The endpoint refuses
to serve preimages for no-comment mints (where the preimage IS the bearer
secret) and serves them unconditionally for melts (where the preimage is
harmless). `VERIFY_ENABLED=false` produces a real HTTP 404, not just a hidden
URL advertisement.
