## Artifacts This Phase Produces

This plan ports the verify race PoC (`test_poc_verify_race.py` from the source)
into the LNbits extension test suite. The 5 scenarios lock the comment-protection
+ verify security guarantees: verify refuses preimages for no-comment mints
(where the preimage IS the bearer secret), serves them for comment-protected
mints (where the preimage redeems nothing), serves melt preimages unconditionally
(harmless), and produces a real 404 when verify_enabled=False. The test uses the
existing FakeNode/conftest pattern with a new `get_standalone_payment`
monkeypatch and a `mint_note_with_comment` helper.

       ```python
       async def mint_note_with_comment(node: FakeNode, amount_msat: int = 50_000):
           """Mint a comment-protected settled note and return
           (victim_secret, comment_hash, note_id, payment_hash, mint).

           The WALLET generates a secret, computes comment_hash = sha256(secret),
           and sends comment=comment_hash on /p/cb. The note materializes keyed
           by comment_hash (not the payment preimage). The victim_secret is
           what the wallet keeps and uses to redeem via /w.
           """
           mint = await get_mint_by_id(TEST_MINT_ID)
           payment = await node.create_invoice(
               wallet_id=mint.wallet, amount=amount_msat // 1000
           )
           payment_hash = payment.payment_hash
           victim_secret, comment_hash = fresh_secret()
           await record_mint_record(
               payment_hash, mint.id, payment.bolt11, amount_msat,
               comment_hash=comment_hash,
           )
           node.settled.add(payment_hash)
           # note_id is the comment_hash (not sha256(preimage))
           note_id = comment_hash
           await _try_settle_mint(note_id, mint)
           return victim_secret, comment_hash, note_id, payment_hash, mint
       ```

       Note: `fresh_secret` returns `(secret, sha256(secret).hexdigest())` — the
       `comment_hash` is the sha256 of the victim's secret, which becomes the
       note's id. The victim keeps `secret` and redeems via `/w?k1=<secret>`.
  </action>
