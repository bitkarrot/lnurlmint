## Phase Goal

**As a** wallet holder, **I want to** mint a note using LUD-25 comment protection so that the note is keyed by my WALLET-supplied comment hash (not the payment preimage), **so that** a routing node that sees the preimage cannot redeem the note (closing the preimage race).

## Acceptance Criteria

- [ ] `GET /lnurlmint/p/cb/{mint_id}?amount=...&comment=<hex64>` records the pending mint with `comment_hash` set; the note materializes keyed by the comment hash.
- [ ] `GET /lnurlmint/p/cb/{mint_id}?amount=...` (no comment) or with a non-hex64 comment falls back to the plain preimage-keyed note (never rejected).
- [ ] `record_mint_record` raises `ValueError("comment already in use")` if `comment_hash` collides with an existing `notes.id` or `mints_records.comment_hash`.
- [ ] `/p/cb` catches the collision `ValueError` and returns `{"status":"ERROR","reason":"comment already in use"}`.
- [ ] The `verify` URL appears in `/p/cb`'s response only when `comment` was a valid hex64 hash AND `mint.verify_enabled` is True.
- [ ] `get_pending_mint_record` matches on `payment_hash = :nid OR comment_hash = :nid` so lazy settlement works for comment-protected mints.
- [ ] `_try_settle_mint` uses `record.payment_hash` (not `note_id`) for `check_transaction_status` and `settle_mint`.
- [ ] A comment-protected note can be redeemed via `/w` using the WALLET-held secret (sha256 of which = comment_hash = note_id).
- [ ] All existing Phase 2 + Phase 3 tests still pass.

## Artifacts This Phase Produces

This plan adds LUD-25 comment protection to the mint callback: the `/p/cb`
endpoint accepts a `comment` query param (LUD-12), and if it's a bare hex64
hash, the resulting note is keyed by that hash instead of the payment preimage.
The collision check prevents comment-hash squatting. The lazy-settlement path
is updated to resolve pending mints by either `payment_hash` or `comment_hash`.
The `verify` URL is advertised in the callback response only when comment
protection was used. Three verify-supporting CRUD queries (`mint_uses_comment`,
`mint_pr`, `melt_pr`) are added here so Plan 04-02 can use them directly.

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Comment-hash collision squat (A1 variant) | high | record_mint_record checks notes.id AND mints_records.comment_hash in one db.connect() block before INSERT; ValueError on collision |
| Preimage race not closed (comment protection bypassed) | high | comment_hash used as note ID in settle_mint (already done); _try_settle_mint resolves by comment_hash so the note materializes under the WALLET's key |
| Verify URL leaked for no-comment mint | medium | verify URL set only when comment_hash is not None AND mint.verify_enabled — the LnurlPayActionResponse.verify field stays None otherwise |
| Lazy settlement fails for comment-protected mint | medium | get_pending_mint_record matches on payment_hash OR comment_hash; _try_settle_mint uses record.payment_hash for settlement |
</threat_model>

<objective>
Add LUD-25 comment protection to the mint callback so a WALLET-supplied comment
hash keys the note instead of the payment preimage, closing the routing-node
preimage race. The collision check prevents squatting; the verify URL is
advertised only when comment protection is in play.

Purpose: Comment protection is the first half of the verify race fix — without
it, the preimage IS the bearer secret and verify must refuse to serve it.
Output: A mint callback that accepts comment, keys notes by comment hash, and
advertises verify only when safe.
</objective>
