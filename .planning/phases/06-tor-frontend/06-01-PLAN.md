## Phase Goal

**As a** Tor visitor, **I want to** receive callback URLs that use the mint's onion address as the base, **so that** a fixed clearnet `base_url` doesn't leak into my QR code and break payment over Tor.

## Acceptance Criteria

- [ ] When `mint.onion_url` is set and the request's Host header matches the onion hostname, `_public_base_url` returns `onion_url.rstrip("/")`.
- [ ] When `mint.onion_url` is set but the request Host does NOT match, `_public_base_url` returns `mint.base_url` (or `request.base_url` fallback) as before.
- [ ] When `mint.onion_url` is None, `_public_base_url` behaves exactly as before (no change).
- [ ] `GET /lnurlmint/lnurlp/{mint_id}` with a Host header matching the onion hostname returns callback/withdrawLink URLs with the onion base.
- [ ] `GET /lnurlmint/lnurlp/{mint_id}` with a non-matching Host returns callback/withdrawLink URLs with the clearnet base.
- [ ] No LNURL endpoint signature changes — all callers of `_public_base_url` work transparently.
- [ ] The X-Forwarded-Host trusted-proxy assumption is documented in the `_public_base_url` docstring.

## Artifacts This Phase Produces

This plan adds Tor onion-address detection to the existing `_public_base_url`
helper. The change is small (5-10 lines in `services.py`) but security-
critical: it prevents clearnet URL leakage into Tor visitors' QR codes while
preserving the spoof-proof semantics (the match is against the operator's own
configured `onion_url`, never a raw request header).

    Replace with:

    ```python
    def _public_base_url(request, mint: Mint) -> str:
        """Derive the public base URL for callback/withdrawLink URLs.

        Spoof-proof: the base is built from the operator's per-mint
        `base_url` / `onion_url` settings, never from a raw request Host
        header. An attacker cannot make the server use an arbitrary base
        URL by sending a spoofed Host — the match is against the
        operator's own configured `onion_url`.

        Tor onion substitution (TOR-01): if `mint.onion_url` is set and
        the request's Host matches the onion hostname, the onion URL is
        used as the base. This prevents a fixed clearnet `base_url` from
        leaking into a Tor visitor's QR code (the callback would point
        at a host Tor can't reach). The match is against the operator's
        own `onion_url` — the only way to trigger this branch is to
        actually connect via the onion service.

        X-Forwarded-Host: behind a reverse proxy, the operator must
        configure uvicorn with `--proxy-headers` so that
        `request.base_url` reflects the original Host (or
        X-Forwarded-Host). No custom X-Forwarded-Host parsing is done
        here — it relies on Starlette/uvicorn's built-in handling.
        """
        if mint.onion_url:
            request_host = urlparse(str(request.base_url)).hostname or ""
            onion_host = urlparse(mint.onion_url).hostname or ""
            if request_host and request_host == onion_host:
                return mint.onion_url.rstrip("/")
        if mint.base_url:
            return mint.base_url.rstrip("/")
        return str(request.base_url).rstrip("/")
    ```
