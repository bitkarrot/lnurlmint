## Phase Goal

**As a** note buyer, **I want to** mint a Lightning-funded bearer note by scanning a QR code and paying an invoice, **so that** I receive a bearer note credited with the amount net of the advertised mint fee, materialized lazily when the payment settles.

## Acceptance Criteria

- [ ] `GET /lnurlmint/lnurlp/{mint_id}` returns a LUD-06 `LnurlPayResponse` with `callback`, `minSendable` (fee-aware floor), `maxSendable`, `metadata` (mint description + `text/identifier` + `Mint fees:` entry when fees non-zero), `withdrawLink`, `commentAllowed: 64`.
- [ ] `GET /lnurlmint/lnurlp/{mint_id}` returns `{"status":"ERROR","reason":"Unknown mint."}` for an unknown mint_id (HTTP 200).
- [ ] `GET /lnurlmint/lnurlp/{mint_id}` returns `{"status":"ERROR","reason":"This mint is sunsetting - minting is disabled."}` when `sunset_mint=true`.
- [ ] `GET /lnurlmint/p/cb/{mint_id}?amount={msat}` creates an invoice via LNbits `create_invoice(wallet_id=mint.wallet, amount=amount//1000, ...)`, records a pending mint in `mints_records` (payment_hash → net amount after fee), and returns `{"pr": ..., "disposable": false}`.
- [ ] The callback rejects amounts below `min_sendable_msat`, above `max_sendable_msat`, or where `amount - mint_fee < min_mint_msat` with LNURL error format.
- [ ] The callback rejects with sunset error when `sunset_mint=true`.
- [ ] `_mint_fee_msat(amount_msat, mint)` = `base_fee_msat + (amount_msat * fee_percent_ppm) // 1_000_000`, rounded UP to nearest whole sat via `-(-fee_msat // 1000) * 1000`.
- [ ] `_min_sendable_msat(mint)` walks amount up from `max(min_sendable_msat, min_mint_msat)` until `amount - mint_fee >= min_mint_msat`.
- [ ] `_melt_fee_limit_msat(amount_msat, mint)` = `max(round(amount * 0.005), 5000, _mint_fee_msat(amount, mint))`.
- [ ] `maxSendable` advertises `mint.max_sendable_msat` (gross amount the payer pays).
- [ ] The note is NOT materialized at callback time — lazy settlement materializes it on first `/w` or `/verify` poll after settlement.
- [ ] `views_lnurl.py` is registered in `__init__.py` via `lnurlmint_ext.include_router(lnurlmint_lnurl_router)`.
- [ ] No query string with `k1` or secret is logged on any endpoint (SEC-05).

## Artifacts This Phase Produces

This plan delivers the mint flow: the LUD-06 payRequest endpoint (advertisement with fee-aware bounds), the mint callback (invoice creation + pending mint record), the fee math service layer, and the lazy settlement helper. The note is not materialized at callback time — it materializes lazily when the holder first polls `/w` (Plan 03) or `/verify` (Phase 4) after the invoice settles. The fee math functions (`_mint_fee_msat`, `_min_sendable_msat`, `_melt_fee_limit_msat`) are protocol contracts (ECON-01 through ECON-04) and must be preserved exactly from the source.
