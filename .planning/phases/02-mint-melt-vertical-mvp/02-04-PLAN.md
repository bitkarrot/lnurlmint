## Phase Goal

**As a** note holder, **I want** my melted note to be burned only on positive settlement confirmation and restored only on positive failure — never on a guess — **so that** a crashed or ambiguous payment never causes a double-spend or permanent funds freeze.

## Acceptance Criteria

- [ ] `_melt_pay` implements the tristate settlement contract: `pay_invoice` raises → `_confirm_payment` → `paid=True` finalize, `paid=False` restore, `paid=None` leave pending (SEC-01, REC-01).
- [ ] `_melt_pay` also handles `pay_invoice` returning a pending Payment (not raising) — checks `payment.status == "success"` and falls through to confirmation if not.
- [ ] `_confirm_payment(payment_hash, wallet_id, delays)` retries `check_transaction_status` with backoff. Default delays = `(1, 2, 4, 8, 16)`. Returns `True`/`False`/`None`.
- [ ] `_confirm_payment` uses `status.success` (paid=True), `status.failed` (paid=False), and `status.paid is None` (pending → retry) — NOT `status.pending` (which is True for both None and False).
- [ ] `_melt_pay` `finally` block always calls `await _track_melt_end(payment_hash)` — cleared even on crash/exception (SEC-03).
- [ ] `reconcile_pending_melts` skips in-flight melts (`await _melt_in_flight(payment_hash)` → continue), resolves stranded notes with `delays=()` single-attempt, logs+leaves pending for unconfirmable (REC-02).
- [ ] `reconcile_pending_melts` resolves each pending note's `wallet_id` via `mint_id → mints.wallet` for `check_transaction_status`.
- [ ] `boot_reconcile` runs as a one-shot `asyncio.create_task` in `lnurlmint_start` before the periodic task (REC-02).
- [ ] `tasks.py` defines `wait_for_melt_reconcile` using `run_interval(60, reconcile_pending_melts)`.
- [ ] `lnurlmint_start` wires `create_permanent_unique_task("ext_lnurlmint", wait_for_melt_reconcile)` and appends to `scheduled_tasks` (EXT-03).
- [ ] `lnurlmint_stop` cancels all `scheduled_tasks` (EXT-03).
- [ ] No "except PaymentError: restore" without `check_payment_status` exists anywhere in the codebase (SEC-01).
- [ ] No logger call on `/w`, `/w/cb`, or reconcile paths includes `k1`, `pr`, preimage, or query strings (SEC-05).

## Artifacts This Phase Produces

This plan delivers the confirm-before-burn state machine — the single highest-risk port detail. `_melt_pay` is the background task that pays the melt invoice and settles the note based on the tristate outcome: `paid=True` → finalize (burn), `paid=False` → restore, `paid=None` → leave pending. `_confirm_payment` retries `check_transaction_status` with backoff for ambiguous states. The in-flight melt registry (from Plan 03) is cleared in `_melt_pay`'s `finally` block. `reconcile_pending_melts` resolves stranded notes from crashed processes, skipping in-flight melts. The background task lifecycle is wired into `lnurlmint_start`/`lnurlmint_stop` via `create_permanent_unique_task`.

    ```python
    async def _confirm_payment(payment_hash: str, wallet_id: str, delays: tuple[int, ...] | None = None) -> Optional[bool]:
        """Retry check_transaction_status with backoff. Returns True/False/None.

        True = confirmed paid (finalize). False = confirmed not paid (restore).
        None = unconfirmable after all retries (leave pending).
        """
        if delays is None:
            delays = _CONFIRMATION_RETRY_DELAYS_SECONDS
        for delay in (0, *delays):
            if delay:
                await asyncio.sleep(delay)
            try:
                status = await check_transaction_status(wallet_id, payment_hash)
                if status.success:
                    return True
                if status.failed:
                    return False
                # status.paid is None → still pending, retry
                # CRITICAL: do NOT use status.pending (True for both None and False)
                if status.paid is None:
                    continue
                # paid is False but status.failed didn't catch — shouldn't happen
                return False
            except Exception as exc:
                logger.warning(f"confirm payment {payment_hash}: attempt failed, retrying: {exc}")
        return None
    ```
