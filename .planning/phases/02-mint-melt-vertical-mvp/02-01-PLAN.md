## Phase Goal

**As a** developer, **I want to** have the complete note CRUD state machine in place with DB transaction atomicity discipline, **so that** the LNURL endpoints (Plans 02-03) and the confirm-before-burn background task (Plan 04) can call these primitives without worrying about race conditions or partial writes.

## Acceptance Criteria

- [ ] `settle_mint(payment_hash)` uses `async with db.connect() as conn:` to atomically `UPDATE mints_records SET minted=1 WHERE payment_hash=:ph AND minted=0`, check `result.rowcount==1`, then `INSERT INTO notes` — all in one connection block.
- [ ] `mark_pending(note_ids, payment_hash, mint_id)` validates all notes are non-pending and non-spent before updating any, using `async with db.connect() as conn:` for atomicity. Raises `PendingNoteError` if any note is already pending, `ValueError` if invalid/spent.
- [ ] `finalize_melt(note_ids, mint_id)` sets `spent=1, pending=0, pending_payment_hash=NULL` for each note, scoped by `mint_id`.
- [ ] `restore(note_ids, mint_id)` sets `pending=0, pending_payment_hash=NULL` for each note, scoped by `mint_id`.
- [ ] `pending_melts()` returns `dict[str, list[str]]` mapping `payment_hash → [note_ids]` for all pending notes across all wallets (no wallet scoping), including `mint_id` for wallet resolution.
- [ ] `record_melt(payment_hash, pr, mint_id)` inserts a melt record (INSERT OR IGNORE).
- [ ] `mark_melt_settled(payment_hash)` sets `settled=1` on the melt record.
- [ ] `get_note(note_id, mint_id)` returns `Optional[Note]` scoped by `mint_id`.
- [ ] `get_mint_by_id(mint_id)` returns `Optional[Mint]` without wallet scoping (for public LNURL endpoints).
- [ ] `get_pending_mint_record(payment_hash, mint_id)` returns `Optional[MintRecord]`.
- [ ] `mint_record_exists(payment_hash)` returns `bool` (self-mint rejection check).
- [ ] `melt_record_exists(payment_hash)` returns `bool` (duplicate-melt rejection check, SEC-06).
- [ ] `get_mint_id_for_note(note_id)` returns `Optional[str]` (reconcile wallet resolution).
- [ ] `PendingNoteError` is defined in `crud.py` and importable.
- [ ] LNURL wire models (`LnurlPayResponse`, `LnurlPayActionResponse`, `LnurlWithdrawResponse`, `WithdrawSuccessResponse`) exist in `models.py` using pydantic v1 syntax.
- [ ] No preimage/secret/k1 column in any table or model (SEC-02).

## Artifacts This Phase Produces

This plan delivers the note CRUD state machine — the DB-layer primitives that the LNURL endpoints and background tasks call. Every multi-statement operation (`settle_mint`, `mark_pending`) uses a single `async with db.connect() as conn:` block for atomicity (REC-03). The compare-and-set pattern (`UPDATE ... WHERE minted=0` + `rowcount==1`) protects lazy settlement materialization from double-mint races. The `PendingNoteError` exception and LNURL wire models are also defined here, as they're needed by the router in Plans 02-03.

<threat_model>
ASVS Level: 1 | Blocking Threshold: high

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Double-mint race (concurrent settle_mint calls materialize two notes) | high | Compare-and-set: UPDATE mints_records SET minted=1 WHERE minted=0 + check rowcount==1. Only the winner proceeds to INSERT. notes.id PRIMARY KEY is the backstop. |
| Partial mark_pending (some notes marked pending, then validation fails on a later note) | high | Validate ALL notes before updating ANY — the validation loop runs first, raising before any UPDATE is issued. The async with db.connect() lock serializes access. |
| Cross-wallet note access (wallet A melts wallet B's note) | high | mark_pending/finalize_melt/restore include AND mint_id = :mid in WHERE clause. mint_id comes from the URL path, which identifies the caller's mint. |
| Preimage column in notes table (store-hashes violation) | high | Schema already excludes it (Phase 1). settle_mint uses payment_hash as note_id, never stores the preimage. |
</threat_model>

Output: 13 new CRUD functions, 1 exception class, 4 LNURL wire models — all importable and tested at the unit level.
</objective>
