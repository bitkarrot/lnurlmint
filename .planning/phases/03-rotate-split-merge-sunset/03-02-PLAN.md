## Phase Goal

**As a** note holder, **I want to** split a bearer note into two notes (one for a specific amount, one for the change), **so that** I can break a large note into smaller denominations without melting it back to sats.

## Acceptance Criteria

- [ ] The `/w/cb` callback handles split: one or many `k1` + `amount` + `h` + `h2` → `swap(note_ids, [h, h2], [amount, change_amount], mint_id)`, returns `{"status":"OK"}`.
- [ ] `h2` is required when `amount` is present; missing/invalid `h2` returns `{"status":"ERROR","reason":"missing h2"}`.
- [ ] `amount` must satisfy `0 < amount < total_msat`; otherwise rejected with `{"status":"ERROR","reason":"amount must be between 0 and {total_msat} msat."}`.
- [ ] `change_before_fee = total_msat - amount`; rejected if `change_before_fee < mint.base_fee_msat` with `{"status":"ERROR","reason":"insufficient value"}`.
- [ ] `change_amount = change_before_fee - mint.base_fee_msat`; rejected if `change_amount < 1` with `{"status":"ERROR","reason":"insufficient value"}`.
- [ ] Split mints two notes: `h` keyed with `amount`, `h2` keyed with `change_amount`.
- [ ] `sign_note` is called for both `h` and `h2` (stub returns None; Phase 5 adds real signatures).
- [ ] Failed split (any rejection) changes nothing — no notes burned, no notes minted (atomicity via `swap`).
- [ ] No logger call includes k1, h, h2, amount, or any query string (SEC-05).

## Artifacts This Phase Produces

This plan delivers the split callback branch, completing the three redeem operations (rotate/merge from Plan 01, split here). Split reuses the `swap` primitive from Plan 01 with two mint notes instead of one. The fee arithmetic (`change = total - amount - base_fee`, reject `change < 1`) is the critical conservation guard — it prevents zero-value notes and ensures the split costs exactly one `base_fee_msat` from the change side. The `h2` validation is added to the callback (required when `amount` is present).
