## Phase Goal

**As a** developer, **I want to** have the complete data model (all four tables + pydantic models) in place, **so that** Phase 2 can implement the note/mint/melt CRUD operations and confirm-before-burn state machine without needing schema changes.

## Acceptance Criteria

- [ ] The `m002_notes_records_melts` migration creates `lnurlmint.notes`, `lnurlmint.mints_records`, and `lnurlmint.melts` tables on SQLite.
- [ ] The `notes` table has columns: `id`, `mint_id`, `amount_msat`, `spent`, `pending`, `pending_payment_hash`, `comment_hash`, `created_at` — and NO preimage column.
- [ ] The `mints_records` table has columns: `payment_hash`, `mint_id`, `pr`, `amount_msat`, `minted`, `comment_hash`, `created_at`.
- [ ] The `melts` table has columns: `payment_hash`, `mint_id`, `note_ids`, `amount_msat`, `pr`, `settled`, `created_at`.
- [ ] Pydantic v1 models `Note`, `MintRecord`, `MeltRecord` exist with fields matching their table columns.
- [ ] No `preimage` column exists in any table (store-hashes-not-secrets invariant from SEC-02).

## Artifacts This Phase Produces

This plan completes the data model by adding the remaining three tables (notes, mints_records, melts) and their pydantic v1 models. These tables are the schema foundation for Phase 2's note CRUD, confirm-before-burn state machine, and background reconciliation. No CRUD operations or API endpoints are added in this plan — the tables exist but are not yet used.

ASVS Level: 1 | Blocking Threshold: high

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Preimage column in notes table (store-hashes-not-secrets violation) | high | Schema explicitly excludes any preimage/secret/k1/raw_k1 column; notes.id is sha256(k1) hex, never the raw secret; acceptance criteria assert no preimage column exists |
| Missing pending_payment_hash on notes (reconcile cannot find stranded notes) | high | notes table includes pending_payment_hash TEXT column for reconcile to identify which melt invoice to confirm |
| Missing minted flag on mints_records (compare-and-set settle race unprotected) | high | mints_records table includes minted INTEGER DEFAULT 0 for the UPDATE ... WHERE minted=0 compare-and-set pattern from source |
</threat_model>
