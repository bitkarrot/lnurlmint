## Phase Goal

**As an** LNbits wallet owner, **I want to** retrieve, update, and delete my per-wallet mints via the management API, with cross-wallet isolation enforced, **so that** I have full CRUD control over my mint configuration and no wallet can access another wallet's mints.

## Acceptance Criteria

- [ ] `GET /lnurlmint/api/v1/mints/{mint_id}` with an invoice key returns the mint if it belongs to the authenticated wallet, 404 otherwise.
- [ ] `PUT /lnurlmint/api/v1/mints/{mint_id}` with an admin key updates the mint config and returns the updated mint.
- [ ] `DELETE /lnurlmint/api/v1/mints/{mint_id}` with an admin key deletes the mint if it has no outstanding notes, returns 409 Conflict if outstanding notes exist.
- [ ] Wallet A cannot retrieve, update, or delete wallet B's mint (every query carries `WHERE wallet = :wallet`).
- [ ] The delete-with-outstanding-notes check queries `lnurlmint.notes WHERE mint_id = :mid AND spent = 0` before deleting.
- [ ] The Vue placeholder page includes a create-mint form and a delete button wired to the API.

## Artifacts This Phase Produces

This plan completes the per-wallet mint CRUD vertical slice by adding get/update/delete operations, the outstanding-notes delete guard, cross-wallet isolation enforcement on every query, an UpdateMint pydantic model, and minimal UI interactivity (create form + delete button). Combined with Plan 01's create/list and Plan 02's complete data model, this delivers the full Phase 1 scope: extension scaffold + data model + per-wallet mint CRUD.

<threat_model>
ASVS Level: 1 | Blocking Threshold: high

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Cross-wallet mint access (wallet A reads/modifies wallet B's mint) | high | Every get_mint/update_mint/delete_mint query includes WHERE wallet = :wallet using wallet.wallet.id from the auth decorator; acceptance criteria include a cross-wallet isolation test |
| Deleting a mint with outstanding notes (funds-loss: notes become orphaned) | high | delete_mint checks count_outstanding_notes(mint_id, wallet_id) before deleting; if count > 0, return 409 Conflict; the check and delete run in one async with db.connect() as conn: block for atomicity |
| Updating immutable fields (id, wallet, mint_privkey) | medium | UpdateMint model excludes id, wallet, mint_privkey, created_at; only configurable fields (fees, limits, username, verify, sunset, base_url, onion_url) are updatable |
</threat_model>

Purpose: The management API must be fully wallet-scoped before Phase 2 adds note operations that depend on mint config. The delete-with-outstanding-notes guard prevents orphaning bearer notes (a funds-loss scenario if a mint is deleted while notes are still outstanding).
Output: Complete CRUD API, cross-wallet isolation, minimal UI interactivity.
